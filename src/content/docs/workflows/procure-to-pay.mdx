End-to-end purchase workflow: order goods, receive into stock, match the supplier bill, and pay. Stock moves on **goods receipt** post; AP moves on **bill** post.

## Standard path

<Steps>
<Step title="Issue purchase order">
Create a PO from an issued supplier and **issue** it. Incoming qty increases on the PO; no stock or GL yet.

<Step title="Receive goods (GRN)">
Create a <DocLink href="/docs/purchases/goods-receipts">goods receipt</DocLink> from the issued PO. **Post** the GRN.

**Partial receipt** — post multiple GRNs against the same PO until each line is fully received. Each GRN increments `qty_received` independently.

**Over-receipt** — when PO-linked, received qty is capped by outstanding unless org `allow_over_receipt` (and optional tolerance) is enabled — see <DocLink href="/docs/purchases/goods-receipts">Goods receipts</DocLink>.
</Step>

<Step title="Record supplier bill">
Create a <DocLink href="/docs/purchases/bills">bill</DocLink> from the posted GRN (or PO). **Post** the bill.

## Variant: bill before receipt (bill-before-receipt)

Use when the supplier invoice arrives before physical goods.

<Steps>
<Step title="Issue PO">
Same as standard — PO must be **ISSUED**.
</Step>
<Step title="Post bill from PO">
Post bill with product lines **without** a GRN. GL hits **Purchases** (not GRNI); no stock movement.

<StateChangeTable
  rows={[
    { action: "Post bill (no GRN)", stock: "No change", reserved: "No change", gl: "Dr Purchases; Cr AP", tax: "VAT input or RCM", documents: "PO qty_billed +" },
  ]}
/>
</Step>
<Step title="Receive against posted bill">
Create GRN **from the posted bill**. Post GRN — stock increases and GRNI clears against the already-posted bill logic on subsequent bill-GRN linkage.

See <DocLink href="/docs/getting-started/document-relationships">Document relationships</DocLink> for the bill-before-receipt create matrix.
</Step>
</Steps>

## Exception: QC reject → return → debit note

When products require QC, GRN post puts qty on **QC hold** until inspection approves.

<Steps>
<Step title="Post GRN with QC required">
Draft quality inspection auto-created — see <DocLink href="/docs/inventory/quality-inspections-and-qc-hold">Quality inspections</DocLink>.
</Step>
<Step title="Approve inspection — reject to supplier">
Set rejected qty with disposition **RETURN_TO_SUPPLIER**. Stock stays on QC hold until return posts.
</Step>
<Step title="Post purchase return">
Create return from the posted GRN. Post — on hand −, GRNI reduced.

Follow <DocLink href="/docs/workflows/handle-a-supplier-return">Handle a supplier return</DocLink>.
</Step>
<Step title="Post debit note">
Create debit note from the posted return (or bill). Post — AP reduced; no further stock movement.
</Step>
</Steps>

## Cancel guards

| Document | Cannot cancel when |
|---|---|
| **Posted GRN** | Period locked; any line `qty_billed > 0`; linked PO has **any** billing; approved QC inspection; live purchase return; FIFO layers partially consumed; inspection qty recorded |
| **Posted bill** | Period locked; payments, debit notes, or write-offs applied |
| **Posted purchase return** | Period locked; live debit note references return |

<Callout type="implementation">
A posted GRN **cannot be cancelled** if the linked PO has **any** billing, even when this GRN was never billed — see <DocLink href="/docs/getting-started/implementation-notes">Implementation notes</DocLink>.
</Callout>
